# 第九轮学习：哪些地方是 LLM 推理，哪些地方是真正的计算

> 时间：2026-05-13  
> 核心问题：TradingAgents 系统中，哪些判断是由 LLM 语言推理完成的，哪些依赖真实的数学/算法计算？

---

## 一、问题的起点

在阅读新闻分析师（News Analyst）的 Prompt 时，发现其核心指令是：

> "请提供具体、可执行、并有证据支撑的洞见，帮助交易员做出明智决策。"

这句话让人产生疑问：这个"洞见"是怎么来的？是 LLM 读完新闻自己判断，还是经过某种量化计算？

---

## 二、四类分析师的底层机制对比

系统中共有四个分析师 Agent，它们的数据处理方式有本质差异。

### 2.1 新闻分析师（News Analyst）

**文件：** `tradingagents/agents/analysts/news_analyst.py`

```python
tools = [get_news, get_global_news]

system_message = (
    "You are a news researcher tasked with analyzing recent news and trends over the past week."
    "Provide specific, actionable insights with supporting evidence to help traders make informed decisions."
)
```

**流程：**
```
get_news / get_global_news（拉取原始新闻文本）
        ↓
LLM 读取文本，判断情感倾向、重要性、关联性
        ↓
直接输出文字报告
```

**本质：纯 LLM 语义推理。**  
没有任何数学计算。LLM 自行决定"这条新闻是利好还是利空"、"这条比那条更重要"。这依赖于 LLM 训练时积累的金融语境知识，而非实时的量化逻辑。

---

### 2.2 市场（技术面）分析师（Market Analyst）

**文件：** `tradingagents/agents/analysts/market_analyst.py`

```python
tools = [get_stock_data, get_indicators]
```

**`get_indicators` 的实现：**

```python
# 文件：tradingagents/agents/utils/technical_indicators_tools.py
def get_indicators(symbol, indicator, curr_date, look_back_days):
    # 调用 route_to_vendor 实际计算 RSI、MACD、布林带等
    return route_to_vendor("get_indicators", symbol, ind, curr_date, look_back_days)
```

**流程：**
```
get_stock_data（拉取 K 线 CSV）
        ↓
get_indicators（真实数学计算：SMA/EMA/RSI/MACD/布林带/ATR...）
        ↓
LLM 读取计算结果数值，进行语言解读
        ↓
输出技术面报告
```

**本质：数学计算 + LLM 解读。**  
技术指标的数值是确定性的数学计算（如 RSI = 14 日平均涨幅 / 平均跌幅），LLM 做的是将这些数字翻译成文字结论（如"RSI=72，进入超买区间，需警惕回调"）。

> 关键区别：同样的输入数据，技术指标的计算结果是固定的；而新闻的"重要性"判断，每次 LLM 可能给出不同答案。

### 2.3 情绪分析师（Sentiment Analyst）

**文件：** `tradingagents/agents/analysts/sentiment_analyst.py`

这个分析师最特殊，值得单独分析。

**数据来源：**
```python
news_block     = get_news.func(ticker, start_date, end_date)      # 新闻文本
stocktwits_block = fetch_stocktwits_messages(ticker, limit=30)    # StockTwits 帖子（含用户标签）
reddit_block   = fetch_reddit_posts(ticker)                       # Reddit 帖子（含点赞数、评论数）
```

**关于 StockTwits 的情绪标签：**

StockTwits 平台允许用户在发帖时手动选择 **Bullish（看涨）** 或 **Bearish（看跌）**，这些标签是**用户自己打的**，不是算法自动标注的，也不是 NLP 情感分析的结果。

**关于 Reddit 数据的抓取与处理方式：**

Reddit 是美国最大的社区讨论平台，系统抓取以下三个金融子版块（subreddit）：

| 子版块 | 风格特点 |
|--------|----------|
| r/wallstreetbets | 散户聚集，风格激进情绪化，常见期权赌博讨论，有时是反向信号 |
| r/stocks | 相对理性，偏分析类帖子 |
| r/investing | 偏长线、价值投资视角 |

**抓取方式：** 直接调用 Reddit 公开 JSON 接口，无需 API Key，每个版块最多抓取 5 条、过去 7 天内提到该股票代码的帖子：

```
reddit.com/r/wallstreetbets/search.json?q=AAPL&sort=new&t=week
```

**格式化后的数据样例：**

```
r/wallstreetbets — 3 recent posts mentioning NVDA:
  [2026-05-10 · 412↑ · 87c] NVDA is going to crush earnings
    body excerpt: I've been watching the options chain and...（截断到240字）
```

每条帖子保留：日期、点赞数（`score`）、评论数（`num_comments`）、标题、正文前 240 字。

**关键：Reddit 数据没有做任何情感计算**，不同于 StockTwits 有用户打的 Bullish/Bearish 标签，Reddit 的帖子是纯文本，直接拼入 prompt，由 LLM 自行判断每条帖子是看涨还是看跌、权重多少。

**流程：**
```
三路数据预拉取（新闻文本 + 带人工标签的StockTwits + Reddit纯文本）
        ↓
全部拼入 prompt（不使用 tool calling）
        ↓
LLM 单次调用，输出情绪报告
```

代码注释原文：
> `# No bind_tools — the data is already in the prompt; a single LLM call produces the report directly.`

**本质：结构化输入 + LLM 语言推理。**  
虽然 prompt 里给了分析指导（如"70/30 Bullish/Bearish 算适度看涨"），但这只是对 LLM 的建议，LLM 如何权衡三路数据、如何处理相互矛盾的信号，仍完全由 LLM 自由裁量。

### 2.4 基本面分析师（Fundamentals Analyst）

**文件：** `tradingagents/agents/analysts/fundamentals_analyst.py`

```python
tools = [get_fundamentals, get_balance_sheet, get_cashflow, get_income_statement]
```

**流程：**
```
调用工具拉取财务报表（资产负债表、现金流、利润表等结构化数据）
        ↓
LLM 读取财务数字，进行语言解读
        ↓
输出基本面报告
```

**本质：结构化财务数据 + LLM 解读。**  
财务数字本身是真实数据（来自 Yahoo Finance / Alpha Vantage / Tushare 等），LLM 做的是将 PE、营收增速、负债率等数字翻译成"公司质量"的语言判断。

## 三、系统全景：LLM 与计算的边界图

```
┌─────────────────────────────────────────────────────┐
│                  分析师层（Analysts）                  │
│                                                     │
│  新闻分析师          情绪分析师                        │
│  [纯LLM推理]         [结构化数据 + LLM推理]            │
│  原始文本→LLM判断    人工标签+文本→LLM综合              │
│                                                     │
│  基本面分析师         市场技术分析师                    │
│  [结构化数据+LLM]    [真实计算 + LLM解读]               │
│  财务报表→LLM解读    K线→数学计算→LLM解读               │
└─────────────────────────────────────────────────────┘
         ↓  四份报告汇入研究员/管理者层
┌─────────────────────────────────────────────────────┐
│              研究员 / 管理者 / 交易员层                │
│                   [全部是 LLM]                       │
│         辩论、综合、风险评估、最终决策                  │
└─────────────────────────────────────────────────────┘
```

## 四、核心结论

### 4.1 整个系统中，真正"基于计算"的只有一处

技术面分析（市场分析师）中的技术指标计算（RSI、MACD、布林带、SMA 等），由 `pandas_ta` 或 `stockstats` 等库在 Python 层完成，结果是确定性的数学输出。

其余所有分析环节，本质上都是 **LLM 的语言推理**。

### 4.2 "有数据" ≠ "有计算"

| 情况 | 举例 | 本质 |
|------|------|------|
| 数据是原始文本，LLM直接读 | 新闻分析 | 纯LLM语义判断 |
| 数据有人工标签（非算法） | StockTwits Bullish/Bearish | 人工标注 + LLM综合 |
| 数据是结构化数字，LLM解读 | 财务报表 | LLM将数字翻译成判断 |
| 数据经过数学计算，LLM解读 | 技术指标 | 计算结果 + LLM解读 |

### 4.3 LLM 推理的固有风险

由于大量判断依赖 LLM：

- **不稳定性**：同样的新闻，不同的模型、不同的温度参数，可能得出不同的"洞见"
- **幻觉风险**：早期 social_media_analyst 因 prompt 要求分析社交媒体但工具只有新闻，导致 LLM **编造** Reddit/X/StockTwits 内容（已在 Issue #557 修复）
- **黑箱权重**：LLM 如何权衡"利好新闻 vs 看空的技术指标"，没有可审计的逻辑链

### 4.4 情绪分析师的历史教训（值得重点关注）

`social_media_analyst.py` 已被废弃，其备注说明了原因：

> "老版本的 prompt 要求分析社交媒体，但唯一可用的工具是 Yahoo Finance 新闻——这导致 LLM 在 prompt 压力下编造了 Reddit/X/StockTwits 的内容（已在线验证）。"

这是一个典型案例：**当 prompt 的期望与工具能力不匹配时，LLM 会用幻觉来"填补"差距**，而不是报错或拒绝。

---

## 五、对未来扩展的启示

如果要提升系统可靠性，应该在以下方向引入真正的计算替代 LLM 推理：

1. **新闻情感**：引入 FinBERT 等金融领域情感分类模型，将新闻自动标注为 +1/0/-1，而非让 LLM 自由判断
2. **情绪聚合**：对 StockTwits 标签做统计（Bullish 比率、7日移动平均），而非将原始帖子扔给 LLM
3. **基本面评分**：将 PE、ROE、负债率等关键指标做规则评分（如 Piotroski F-Score），给 LLM 一个数值锚点
4. **信号融合**：引入加权投票或置信度评分机制，而非完全依赖管理者 Agent 的 LLM 语言辩论

这些改造可以保留 LLM 的语言表达能力（生成可读报告），同时减少关键判断对 LLM 主观推理的依赖。
